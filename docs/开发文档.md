# VoiceTranslator 开发文档

> 面向开发者/二开者。讲清架构、关键设计决策、打包流程、以及踩过的坑。

## 1. 架构总览

```
┌────────────── 采集层 ──────────────┐
│ LiveEngine (audio/live_engine.py)  │
│  sd.InputStream 回调线程            │
│  多参数回退打开设备（见 §4.2）        │
│  → float32 mono 16k 队列           │
└──────────────┬─────────────────────┘
               ▼
┌────────────── 断句层 ──────────────┐
│ VoiceSegmenter (vad/silero_vad.py) │
│  Silero VAD 逐帧(512)评分           │
│  说话开始→缓存音频；静音 450ms→切段  │
└──────────────┬─────────────────────┘
               ▼
┌────────────── 流水线层 ────────────┐
│ TranslationPipeline (audio/pipeline.py) │
│  STT(Moonshine) → MT(CT2) → TTS(TinyTTS) │
│  三模块统一接口可替换（base.py）      │
└──────────────┬─────────────────────┘
               ▼
┌────────────── 输出层 ──────────────┐
│ OutputManager (audio/output.py)    │
│  play_to_cable() → VB-CABLE 播放端 │
│  可选本地回放双路                   │
└────────────────────────────────────┘
```

**线程模型**：采集（PortAudio 回调线程）→ VAD/引擎主循环（独立线程）→
流水线（`_processing_lock` 串行）→ 播放（sounddevice 线程）。GUI 通过
`ui_queue` 收事件，UI 线程轮询（tkinter 控件只在主线程碰）。

**模块接口**（都在各自目录的 `base.py`，方便换模型）：

| 抽象 | 方法 | 当前实现 |
|---|---|---|
| `SttEngine` | `load/transcribe_file/close` | `MoonshineStt` |
| `TranslatorEngine` | `load/translate/close` | `Ct2Translator` |
| `TtsEngine` | `load/synthesize/close` | `TinyTts` |
| `Vad` | `load/is_speech/reset` | `SileroVad` |

## 2. 关键设计决策

### 2.1 延迟优化（达标 <2s，实测 ~1.5s）

- 三引擎 `load()` 时各跑一遍**假数据预热**（消除首次推理的图优化开销）
- ORT 会话限线程（enc/dp=1、flow/dec=2）+ CT2 `intra_threads=1`：
  多引擎并存时线程争抢曾把 MT 从 50ms 拖到 777ms
- VAD 句尾静音判定 600→450ms（再小容易切断尾音）

### 2.2 设备打开：多参数回退（重要！）

Windows 麦克风格式千奇百怪（Realtek 阵列麦拒 float32、WDM-KS 拒重采样…），
固定参数打开必翻车。`LiveEngine.start` / `MicLevelMonitor.start` 的回退维度：

```
设备变体（WASAPI > MME > DirectSound > WDM-KS）
  × 采样率 (16k / 设备默认 / 48k / 44.1k)
  × 声道   (1 / 原生)
  × 格式   (float32 / int16)
```

- `open()` 和 `start()` 都在 try 里（WASAPI 格式协商可能延迟到 start 才报错）
- int16 流在回调里 /32768 转 float32；多声道 mean 合一；非 16k 线性插值重采样
- **全部失败不阻塞启动**：进入"无输入"模式，界面照常，状态栏一句事实说明。
  设计哲学（用户多轮反馈的结果）：软件永不替用户判断设备好坏，只报告事实

### 2.3 设备编号不可缓存

PortAudio 设备编号是**会话敏感**的：RDP 重连/插拔设备后编号整体漂移。
凡长期持有设备号的地方，用前必须按名字重新解析（`App._refresh_device_maps`，
每次点开始都会调）。

### 2.4 同名设备陷阱（-9997 闪退式 bug 的近亲）

Windows 把同一块物理麦克风在 4 个 Host API 下各注册一条**同名**设备。
按名字建映射时 WDM-KS 变体（最挑剔）容易覆盖 WASAPI 变体（最宽容）。
两处防护：GUI 映射同名去重保留最易打开变体；LiveEngine 打不开指定设备时
自动尝试其同名变体（`_candidate_input_devices`）。

### 2.5 双 ORT 堆损坏闪退（0xc0000374）

**现象**：随机闪退，无任何报错。事件日志：堆损坏，偏移固定。

**根因**：进程里两份不同版本 onnxruntime——Python 包的 pyd（静态链接 1.30）
+ moonshine.dll 依赖的 onnxruntime.dll（1.23）。pyd 模块名不同绕过了 Windows
按名去重，两份 ORT 各自线程池/堆，并发推理互踩内存。

**修复**：`MoonshineStt._preload_shared_ort()`——load() 最先 `ctypes.WinDLL`
capi 的 1.30，把 `onnxruntime.dll` 模块名占住，moonshine.dll 随后按名复用。
moonshine 只按序号导入 `OrtGetApiBase` 等 2 个函数，1.30 完全兼容（PE 导入表
分析+识别结果一致性验证过）。

**教训**：混装原生 DLL 的进程，要用 Toolhelp32 快照**数一遍进程内模块**；
"同名去重"只对 LoadLibrary 生效，静态链接的 pyd 绕过去重。

### 2.6 灵敏度体系

小声+底噪场景 Silero VAD 概率只有 0.07（阈值 0.5 全灭）。方案：软件增益
`input_gain`（is_speech 内 clip 前放大）+ 低阈值。GUI 三档：
低 (0.5/gain3)、中 (0.35/gain6，默认)、高 (0.22/gain10)。

## 3. 目录与数据流

- 模型统一放 `models/`，路径解析统一走 `paths.py`
  （源码=项目根；PyInstaller 打包后=`sys._MEIPASS`）。**不要**在各模块里
  自己 `__file__` 推算——打包必炸。
- 用户数据（历史/崩溃日志）写 `%APPDATA%/voice-translator/`（`paths.appdata_dir()`），
  不要写安装目录（可能无权限）。
- 历史是 JSONL 追加写，上限 1 万条自动裁剪，损坏行跳过不崩。

## 4. 打包（PyInstaller）

```bat
venv\Scripts\pyinstaller voice_translator.spec --noconfirm
dist\VoiceTranslator\VoiceTranslator.exe --selftest   :: 验收，退出码 0=通过
```

关键点（`voice_translator.spec`）：

- onedir 模式（onefile 解压 340MB 太慢）
- `console=False`；冒烟测试别只看进程——用 EnumWindows 查窗口标题
- moonshine.dll + onnxruntime.dll 是 `ctypes.CDLL` 运行时加载的，
  **PyInstaller 静态扫描收不到**，必须手动进 spec 的 datas
- 每次改代码后：重新打包 + 跑 `--selftest`

## 6. 踩坑记录（按时间序，二开前必读）

| 坑 | 结论 |
|---|---|
| moonshine 中文模型收 numpy 不行 | `transcribe_without_streaming` 要 `list`，不收 ndarray |
| `sd.play()` 没有 blocking_callback | 双路播放用两个线程各播各的 |
| 改快捷键死锁 | 公开方法拿锁/内部 `_xxx_locked` 不拿锁，绝不嵌套 |
| ttk.Scale command 传字符串 | label 更新用 `float(var.get())` |
| spec 里 Windows 路径 `\a` 是响铃转义 | spec 文件里路径用正斜杠 |
| 打包后加载 moonshine.dll 失败 | DLL 是运行时 CDLL 的，spec datas 手动加 |
| `sd.rec` 在 WDM-KS 返回 NaN | 回调模式正常——引擎全部用回调 |
| 设备"探测失败"≠设备坏 | 真实麦克风可能不支持探测用的固定参数；**探测拦截方案被用户否决并删除**——设备能不能用只有真启动才知道 |
| VAD 概率 0.07 全不触发 | 软件增益 + 降阈值（见 §2.6） |
| 设备编号漂移 | 用前按名字重新解析（§2.3） |
| 同名设备跨 Host API | 去重保留 WASAPI 变体（§2.4） |
| 双 ORT 堆损坏 | 预加载占名（§2.5） |

## 7. 二开指引

- **换 STT**：实现 `stt/base.py` 接口，`gui/app.py` 的 `create_default_stt()`
  换成你的工厂即可
- **换 TTS**：同上（`tts/base.py`）；文本前端 `tts/text_frontend.py` 是无
  torch 轻量版（CMU 词典+字母拼写兜底），换 Piper 等可整体替换
- **加语言**：翻译模型换对应 opus-mt 对（Helsinki-NLP 全系列），TTS 换多语种
  模型；VAD/引擎层不用动
- **界面**：tkinter 零依赖。改 UI 后用 `scripts\看UI效果.bat` 直接看源码版
  效果，确认后再打包
